# 2026-11-12

## skillporter — Phase 0 complete

Project: open-source CLI + library converting AI agent skills between agent formats,
with an explicit fidelity report. Repo root is the workspace root itself.

**Name decision:** `skillporter` (free on npm and GitHub as of today; not yet reserved).
CLI binary `skillporter`. ADR-0004.

**Architecture:** hub-and-spoke via a versioned IR (`source -> Parser -> IR -> Emitter ->
target`). Capability profiles are YAML data in `agents/*.yaml`, validated against
`schema/agent-profile.schema.json`. ADR-0001, ADR-0002.

**Phase 0 findings that changed the plan (full detail in docs/research.md §2):**
- Codex CLI uses `.agents/skills`, not `.codex/skills` — shared root with dsh and OpenCode,
  so `.agents/skills` is the default output root (ADR-0003).
- Claude Code does not enforce kebab-case names and `name` is optional.
- dsh's 500-char description is a *catalog display truncation*, not a validation error.
- dsh also accepts flat `<name>.md` and honours `disable-model-invocation` / `user-invocable`.
- dsh spelling is `whenToUse` (camelCase) vs Claude's `when_to_use` → `fieldAliases` added.
- dsh fails silently (warn log, skill invisible) → `lint` is the only diagnostic.
- Claude Code has two targets: local dirs (permissive) vs claude.ai upload (hard-errors on
  extra keys). Should be two profiles in Phase 1.
- Codex has a sidecar `agents/openai.yaml` (interface, policy, dependencies).

**Deliverables:** docs/research.md, agents/{claude-code,deepseek-harness,codex-cli}.yaml,
