# Lint rules

> Generated from `packages/core/src/rules.ts` by `scripts/generate-rule-catalog.mjs`.
> Do not edit this file by hand: edit the catalogue and regenerate.

24 rules: 20 derived from capability-profile data and 4 that report
skillporter's own observations. No rule names an agent. Every rule id is stable:
it is never reused and never renumbered, so a report can be diffed across releases.

## How severity is decided

Severity is a function of what the agent *does*, read from the target capability profile. The rule is:

| The agent… | Profile value | Severity |
| --- | --- | --- |
| refuses to load the skill | `enforcement: reject` | `error` |
| drops it from the catalog silently | `enforcement: silent-skip` | `error` |
| shortens a display string | `enforcement: truncate` | `warning` |
| ignores the field | `fields[].status: ignored` | `warning` |
| does not enforce anything | `enforcement: none` | `info` |
| behaviour is undocumented | `unknown`, `null` | `warning` |

`silent-skip` counts as an error even though nothing is visibly rejected: the outcome is the same for the
user, because the skill never appears and the only feedback is a log line. Anything undocumented is a
warning rather than an error, because the project reports gaps instead of guessing at them.

- **SP009** — Applies only to the flat form. A directory skill is read by every surveyed agent, so the rule is silent for directory layouts.
  Fix: Move the file into a directory of its own as SKILL.md. `skillporter convert` does this automatically.
- **SP015** — Purely declarative: an extension fires when its trigger matches a frontmatter field. Kimi Code `type: flow` is the motivating case, and no agent-specific code exists for it.
  Fix: Read the extension description and decide whether the behaviour matters. Converting away from this agent cannot carry it.
- **SP022** — SKILL.md is included in the comparison, so a stray skill.md beside SKILL.md is caught. Tool behaviour: the same two files are a problem for every target.
  Fix: Rename one of the files. On a case-insensitive filesystem one will overwrite or shadow the other.
- **SP023** — Kept separate from every agent limit on purpose. This says skillporter stopped reading, not that the target would refuse the skill.
  Fix: Raise the limit with --max-file-bytes, --max-files, --max-total-bytes or --max-depth if the skill really is that large.
- **SP024** — Absent frontmatter is only fatal where the target needs it. A target that falls back to the path can still load a skill with no frontmatter, so the same fact produces a different severity per profile.
  Fix: Add or repair the frontmatter block. skillporter will not guess what an unparseable document meant.

- **SP021** — Only siblings in the same discovery root are compared, because that is the only collision the target resolves. The finding quotes the profile duplicateResolution text when there is one and says plainly when the target documents no winner.

## Suppression

`--ignore-unknown` suppresses findings whose diagnostic code is `UNKNOWN_CAPABILITY`, which is what every
"we have no verified answer" finding carries: SP011, SP012, SP013, SP015, and SP017 when the target's
shell behaviour is undocumented. It never suppresses an error, and never suppresses a verified fact.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | clean, or informational findings only |
| `1` | at least one `error` |
| `2` | no errors, at least one `warning` |

`--ignore-unknown` can turn a `2` into a `0`, never a `1` into a `0`.
