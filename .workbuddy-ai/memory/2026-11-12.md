# 2026-11-12

## skillporter — Phase 0 complete

Project: open-source CLI + library converting AI agent skills between agent formats,
with an explicit fidelity report. Repo root is the workspace root itself.

**Name decision:** `skillporter` (free on npm and GitHub as of today; not yet reserved).
CLI binary `skillporter`. ADR-0004.

**Architecture:** hub-and-spoke via a versioned IR (`source -> Parser -> IR -> Emitter ->
target`). Capability profiles are YAML data in `agents/*.yaml`, validated against
`schema/agent-profile.schema.json`. ADR-0001, ADR-0002.

**Phase 0 findings that changed the plan (full detail in docs/research.md §2):**
- Codex CLI uses `.agents/skills`, not `.codex/skills` — shared root with dsh and OpenCode,
  so `.agents/skills` is the default output root (ADR-0003).
- Claude Code does not enforce kebab-case names and `name` is optional.
- dsh's 500-char description is a *catalog display truncation*, not a validation error.
- dsh also accepts flat `<name>.md` and honours `disable-model-invocation` / `user-invocable`.
- dsh spelling is `whenToUse` (camelCase) vs Claude's `when_to_use` → `fieldAliases` added.
- dsh fails silently (warn log, skill invisible) → `lint` is the only diagnostic.
- Claude Code has two targets: local dirs (permissive) vs claude.ai upload (hard-errors on
  extra keys). Should be two profiles in Phase 1.
- Codex has a sidecar `agents/openai.yaml` (interface, policy, dependencies).

**Deliverables:** docs/research.md, agents/{claude-code,deepseek-harness,codex-cli}.yaml,
schema/agent-profile.schema.json, scripts/validate-profiles.mjs, tests/profiles.test.mjs,
docs/adr/0001-0004, README.md, LICENSE (Apache-2.0).

**Verification:** `npm run validate:profiles` → 3/3 valid. `npm test` → 6/6 pass.
Git initialized; one commit `1df4a71`.

**Next (Phase 1):** IR types + zod/ajv validation, pipeline, report (JSON/MD/text), CLI
(`convert`, `inspect`, `lint`, `agents`), golden-file + round-trip tests, CI.

## skillporter — Phase 1a complete

Monorepo: packages/core (IR, parsers, detection, diagnostics) + packages/cli (commander).
tsc -b project references; `npm test` = build + node --test. 40/40 tests pass.

**IR is source-oriented:** identity/description/body(byte-exact, CRLF preserved)/bodyHash/
frontmatter{raw + per-field raw YAML, line, column, status, effect}/files{sha256, mode,
encoding, lineEnding}/origin/text{lineEnding, hasBom}/shellInjection/diagnostics/limits.

**Key decisions made during 1a:**
- Added `identity` and `bodyExecution` to the agent-profile schema so parsers stay
  data-driven. `identity.source` = frontmatter | path | frontmatter-or-directory |
  frontmatter-or-filename (OpenCode is `path`).
- Added `role: native|compatibility` to pathEntry. Detection only treats native roots as
  owners, so `.agents/skills` = 3 native owners → ambiguous (opencode is compatibility),
  and `.claude/skills` resolves to claude-code (opencode reads it as compatibility).
- `followsSymlinks` now allows null = undocumented (OpenCode, Kimi).
- shellInjection.line is a FILE line (offset passed into scanShellInjection). Earlier bug:
  summary showed body-relative lines while diagnostics showed file lines.
- Flat `.md` skills get files:[] — walking the parent skills dir would have collected
  sibling skills. Guarded by a test.
- Tool limits labelled `scope: 'tool'` everywhere; separate from agent limits.

**Bugs found by manual CLI runs (fixed):** the line-number mismatch above, and the
"detected by" row being misleading when --from overrides detection.

**Security tests:** touch-marker test (inline + fenced + inside ```bash), symlink escape
reported not followed, internal symlink followed, limits, path traversal/absolute rejection,
Persian text byte-exact.

**Kimi doc conflict** recorded in research.md §8.9. The help-centre article could not be
located at a stable URL (the help centre returns 200 for every path), so it is recorded as
REPORTED not VERIFIED. Emitter will always write name+description for Kimi; never /flow:.

Next: Phase 1b (lint --for), rule IDs, severities, source URLs, exit 0/1/2.

## Phase 1b — `lint --for <agent>` (commit db21b8f)

Built the lint command: `packages/core/src/rules.ts` (catalogue, SP001–SP024) and
`packages/core/src/lint.ts` (engine), plus `lint` in the CLI and `renderLint`.
Decisions worth remembering:

- Rule ids are a separate stable catalogue above diagnostic codes; `code` = what
  was observed, `ruleId` = what it means for the target. Severity is computed
  from `enforcement`/`fieldStatus` so the same fact differs per agent.
- 20 rules `derivation: profile`, 4 `derivation: tool`. The synthetic-profile
  test in `tests/lint.test.mjs` is the guard against the catalogue becoming
  per-agent code — keep it green when adding rules.
- `docs/lint-rules.md` is generated by `scripts/generate-rule-catalog.mjs`; CI
  runs `npm run rules:check`. Never hand-edit that document.
- Profile schema gained `sources[].covers` and `extensions[].trigger`; the
  validator now requires every profile to cover paths/discovery/identity/name/
  description/fields, and requires `name.pattern` to compile.
- New diagnostic codes: FIELD_INVALID, SYMLINK_ROOT, DUPLICATE_NAME, FILE_ANOMALY.
- `deriveIdentity` was extracted from `parse.ts` so lint derives the *target*
  identity with the same logic the parser uses for the source.
- Exit codes: 0 clean, 1 error, 2 warnings only. `--ignore-unknown` suppresses
  UNKNOWN_CAPABILITY only.
- Case-collision detection was pulled into a pure `caseCollisions()` because
  macOS/Windows cannot hold `notes.md` + `Notes.md`; the integration test skips
  there and the pure function is tested instead.
- Kimi help-centre URL (https://www.kimi.com/en/help/features/use-skills-in-code)
  is recorded in research §8.9; the conflict with the reference docs is still
  unresolved, so the emitter must keep writing name+description for Kimi.

Next: Phase 1c — `convert`, conversion report, install with backup. Reuse the
`Diagnostic` finding shape (ruleId/fix/source) for the conversion report.
